# 手把手教你用AI做一个INDEVOLT APP

不会编程也没关系。这篇教程不教 Python，也不要求你先弄懂 HTTP、MQTT 或 Modbus。你只需要下载一份指令交给 AI，再按页面提示一步一步操作。

:::note 本文中的 INDEVOLT APP

这里的“INDEVOLT APP”是你自己制作、用于连接 INDEVOLT 设备的小程序，不是官方 INDEVOLT App。

:::

## 做完以后是什么样

这次先做一个最简单的本地设备面板：

- 输入设备 IP，连接 `8080` 端口。
- 显示设备序列号、电池电量、充放电功率和运行状态。
- 自动刷新，并显示最后更新时间。
- 提供可以滚动、全选和复制的请求日志。

第一版只读取数据，不控制设备，也不发布到互联网。预计第一次需要 30～60 分钟，具体时间取决于 AI 工具和电脑环境。

## 开始前准备

- 一台已[开启 OpenData HTTP](../http/overview.md#enable-api) 的 SolidFlex 或 PowerFlex 设备。
- 一台与设备连接同一局域网的电脑。
- 设备 IP，例如 `192.168.8.247`。
- 一个能够读取附件和网页、创建文件、运行命令并检查结果的 AI 编程工具。
- 一个新的空文件夹，用来保存 App。

不知道设备 IP 或 OpenData 是否开启也没关系，后面直接告诉 AI“不知道”。

## 第 1 步：下载专家指令

先下载下面的 Markdown 文件：

<a className="button button--primary" href="/downloads/indevolt-software-development-expert-instructions.md" download="INDEVOLT-软件开发专家指令.md">下载 INDEVOLT 软件开发专家指令</a>

下载后会得到一个 `.md` 文件。新建 AI 任务，把这个文件直接拖进对话框或作为附件上传。

如果你的 AI 工具不能上传文件，就打开[专家指令网页版](./expert-instructions.md)，复制全文后发送给 AI。

**这一步完成的标志：** 对话中能够看到专家指令附件，或者 AI 已经收到完整指令正文。

## 第 2 步：把 App 需求发给 AI

上传专家指令后，把下面整段复制给 AI。只需要填写最后四项：

```text
请先完整阅读我上传的《INDEVOLT 软件开发专家指令》，暂时不要写代码。

我要做一个连接 INDEVOLT 设备的本地 App。第一版只读取数据，不控制设备，也不发布或部署。

App 需要：
- 输入设备 IPv4 地址，并显示固定端口 8080；
- 显示设备序列号、电池电量、充放电功率和运行状态；
- 显示最后更新时间，并按 INDEVOLT 官方限制自动刷新；
- 提供全宽、可滚动、可全选复制的请求日志；
- 请求局域网设备时不使用系统 HTTP 代理；
- 在我的电脑上直接运行。

成功标准：App 能连接真实设备并显示真实数据；日志中能看到请求地址、端口、HTTP 状态和响应内容。详细错误只写入日志，不在界面上重复显示。

请先检查 INDEVOLT 文档和当前电脑环境，主动推荐最简单的实现方式。然后给我方案和《实现确认单》，等我单独回复“确认实施”后再创建文件和测试。

电脑系统：【macOS、Windows 或 Linux】
设备型号：【填写型号；不知道就写“不知道”】
设备 IP：【填写 IP；不知道就写“不知道”】
OpenData HTTP：【已开启或不知道】
```

**这一步完成的标志：** AI 没有立刻写代码，而是在查看文档、询问缺失信息或准备方案。

## 第 3 步：回答 AI 的问题

AI 可能会问设备型号、设备 IP、电脑系统或 OpenData 是否开启。知道就回答，不知道就回复：

```text
我不知道，请告诉我去哪里查看。其他能够从 INDEVOLT 文档、附件、项目或电脑环境中查到的信息，请你自行调查。
```

下面这些问题不需要你决定：

- 用哪种编程语言。
- 使用 HTTP、MQTT 还是 Modbus。
- 选择什么界面框架。
- 代码应该分成几个文件。

如果 AI 把这些问题丢给你，回复：

```text
请根据专家指令、INDEVOLT 文档和当前环境，直接推荐最简单的方案。
```

## 第 4 步：看一眼方案

写代码前，AI 应该给出《实现确认单》。你只检查下面五项：

- [ ] 第一版只读取数据，不控制设备。
- [ ] 会显示序列号、电量、功率、运行状态和请求日志。
- [ ] App 只在你的电脑上运行，不会自动发布。
- [ ] 写清楚会创建哪些文件，以及怎样启动和验证。
- [ ] 正在等待你回复“确认实施”。

如果都对，单独回复：

```text
确认实施
```

不要在这四个字后面附加其他内容。

如果不对，直接说哪里要改。例如：

```text
第一版太复杂。请去掉设备控制和发布，只保留本地只读面板，然后重新给出《实现确认单》。不要开始写代码。
```

## 第 5 步：等 AI 做完

回复“确认实施”后，AI 应该创建文件、安装依赖、运行检查，并告诉你怎样启动 App。

如果 AI 只在聊天里贴出代码，没有真正创建和运行项目，回复：

```text
请继续完成已确认的实施范围：把代码写入项目文件，运行必要检查并启动 App。不要只在聊天中展示代码。
```

**这一步完成的标志：** App 已经打开，或者 AI 给出了一条经过验证的启动命令。

## 第 6 步：亲自点一遍

App 打开后，按顺序检查：

1. 能看到“设备 IPv4 地址”和端口 `8080`。
2. 输入设备 IP，点击连接。
3. 能看到序列号、电池电量、功率和运行状态。
4. “最后更新时间”会变化。
5. 日志框横向占满界面，并且可以滚动。
6. 点击日志框，使用 `Ctrl+A` 或 `Command+A` 可以全选复制。
7. 日志中能看到请求地址、`HTTP 200` 和设备返回内容。

全部通过，第一版就完成了。

## 第 7 步：出错就把日志交给 AI

不需要自己分析代码。把现象和完整日志复制给 AI：

```text
当前现象：【例如：点击 Connect 后仍然显示 Not connected】
我刚才的操作：【例如：输入 192.168.8.247，然后点击 Connect】
我期望看到：【例如：显示设备电量和功率】

完整请求日志：
【粘贴日志】

请先根据日志定位原因，只修复这个问题，然后重新执行相同的验证。不要顺便增加其他功能。
```

复制日志前，先遮盖不希望公开的设备信息。不要把密码、令牌或密钥发给 AI。

如果日志出现 `Failed to fetch`，要同时说明你使用的是浏览器在线预览，还是下载到电脑上的本地程序。浏览器会受到跨域和本地网络权限限制。

## 第 8 步：收好 App

确认 App 可以使用后，发送：

```text
请按专家指令输出最终《交付报告》，写清源码位置、下次启动方法、实际验证结果、已知限制和回退方法。不要把工作过程写进交付文档。
```

最后确认你已经拿到：

- [ ] 完整源码。
- [ ] 下次启动 App 的方法。
- [ ] AI 实际运行过的检查及结果。
- [ ] 已知限制和回退方法。
- [ ] 第一版没有未经确认的设备控制或发布功能。

## 以后想增加功能

先保证只读版本正常，再开一个新任务增加图表、历史记录、告警或设备控制。

如果新功能需要真实控制设备，AI 必须先给出《设备写入确认单》。只有你单独回复 `确认设备写入`，才允许执行其中写明的一次设备操作；`确认实施` 不能代替它。

想了解这个 App 背后的 OpenData HTTP 调用，可以继续阅读[使用 OpenData HTTP API 构建设备面板](../tutorials/opendata-local-device-panel.md)。
